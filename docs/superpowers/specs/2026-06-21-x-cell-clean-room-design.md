# X-Cell Clean-Room Reproduction Design

## Purpose

Build a clean-room, runnable reproduction of X-Cell from the paper
`/Users/weizongting/Desktop/CIFM_benchmark/CIFM_benchmark_paper/X-Cell.pdf`.
The implementation will live in this empty repository as a Python package and
will not copy code from the official repository. The official repository was
checked only to understand the public package name and current release state; it
currently exposes a stub API and states that model weights and inference
code are coming soon.

The result should be useful for research engineering: it should let a user
train, predict, and evaluate on real AnnData/H5AD perturbation datasets when
provided, while also including synthetic tests so the code is verifiable without
large private data.

## Scope

This project will implement:

- A PyTorch X-Cell model matching the paper's published architecture.
- Training-time diffusion reveal masks at 25, 50, 75, and 100 percent.
- Four-step cumulative diffusion inference.
- Cross-attention conditioning on biological prior embeddings.
- The paper's set-level losses and training metrics.
- AnnData/H5AD data loading, preprocessing, set construction, and collation.
- Command line entry points for training, prediction, evaluation, and synthetic
  data generation.
- Synthetic unit and smoke tests covering the core system end to end.
- Preset configurations for `tiny`, `mini`, and `ultra`.

This project will not attempt to reproduce the paper's reported benchmark
numbers without the released X-Atlas/Pisces data, external prior embedding
files, trained weights, and H200-scale compute. The code will expose the required
interfaces and configs so those experiments can be run when the data and compute
are available.

## Primary Deliverables

- Python package: `src/xcell_repro/`
- Tests: `tests/`
- CLI module: `xcell-repro`
- Project metadata: `pyproject.toml`
- Example configs: `configs/`
- Synthetic data examples: generated by CLI into user-specified output paths
- Documentation: `README.md` plus this design and the implementation plan

## Architecture

The package will be split by responsibility:

- `xcell_repro.model`
  - Transformer backbone.
  - Self-attention and cross-attention blocks.
  - RMSNorm, optional QK-Norm, SwiGLU, and MLP decoder components.
  - X-Cell model class and config presets.

- `xcell_repro.diffusion`
  - Training mask construction.
  - Input mixing: `x_input = (1 - mask) * x_ctrl + mask * x_target`.
  - Four-step cumulative inference with reveal fractions
    `[0.25, 0.5, 0.75, 1.0]`.

- `xcell_repro.priors`
  - Gene prior embedding containers.
  - Loading of ESM-2, STRING, GenePT, DepMap, and JUMP Cell Painting embeddings
    from local arrays or parquet/csv/npz files.
  - Zero imputation and boolean missing-source masks.

- `xcell_repro.data`
  - AnnData/H5AD IO.
  - Raw count to CP10k log1p preprocessing.
  - Gene vocabulary construction.
  - Set-level sampling of control and perturbed cells.
  - Forced inclusion of the perturbed gene at position 1 when subsampling.

- `xcell_repro.losses`
  - Energy-distance MMD fallback implemented in torch.
  - Optional geomloss energy distance when installed.
  - Fold-change CCC.
  - Per-gene CCC.
  - Delta norm penalty.
  - Delta pseudobulk MSE.
  - InfoNCE contrastive loss.
  - Prior reconstruction loss.

- `xcell_repro.training`
  - Train loop, validation loop, checkpoint save/load.
  - AdamW, cosine warmup, gradient clipping, mixed precision when available.
  - Optional FSDP hooks kept behind configuration.

- `xcell_repro.inference`
  - AnnData prediction wrapper.
  - Batch prediction over perturbation genes.
  - Export to AnnData with predicted log1p CP10k expression.

- `xcell_repro.evaluation`
  - Pearson delta.
  - MAE.
  - Overlap@N.
  - Direction match.
  - Delta norm ratio and centroid retrieval accuracy for smoke tests.

- `xcell_repro.cli`
  - `make-synthetic`
  - `train`
  - `predict`
  - `evaluate`

## Model Design

Each batch sample represents a set of `S` cells and `G_prime` genes:

- `x_ctrl`: control expression, shape `[B, S, G_prime]`
- `x_target`: perturbed expression, shape `[B, S, G_prime]`
- `gene_ids`: vocabulary indices, shape `[B, S, G_prime]` or broadcastable
  `[B, G_prime]`
- `perturbation`: perturbation gene id or symbol
- `mask`: diffusion reveal mask, shape `[B, S, G_prime]`

The model flattens batch and set dimensions to process cells as token sequences.
It prepends a learned CLS token and encodes each gene token as:

```text
gene_identity_embedding + continuous_value_embedding + perturbation_mask_embedding
```

The continuous value encoder is a two-layer MLP with ReLU and LayerNorm. Values
are clipped at an upper bound of 512, matching the paper.

The perturbation context contains six tokens:

- ESM-2 embedding projected from 5120 dimensions.
- STRING embedding projected from 512 dimensions.
- GenePT embedding projected from 3072 dimensions.
- DepMap embedding projected from 1150 dimensions.
- JUMP Cell Painting embedding projected from 259 dimensions.
- Stop-gradient gene identity embedding for the perturbed gene.

Missing external embeddings are zero-imputed and marked in the cross-attention
key padding mask.

The transformer will support two modes:

- `mini`: 12 layers, hidden size 512, 8 heads, cross-attention layers
  `[2, 5, 8, 11]`, LayerNorm/post-LN style, ReLU FFN, untied scalar MLP output
  by default.
- `ultra`: 34 layers, hidden size 2560, 40 heads, cross-attention every third
  layer plus the final layer, Pre-LN RMSNorm, SwiGLU, no attention bias,
  QK-Norm, and tied embedding output.

A `tiny` preset will use the same code paths with small dimensions so tests and
local smoke runs finish quickly.

## Diffusion Design

Training uses a discrete reveal strategy. For each sample, the reveal fraction is
drawn uniformly from:

```text
0.25, 0.5, 0.75, 1.0
```

The selected gene positions are set to target expression in the input, and the
mask embedding tells the model which values are revealed perturbed signal. The
training target is always the full perturbed expression profile.

Inference uses cumulative four-step refinement:

1. Start with control expression and an all-zero reveal mask.
2. Assign random ranks to gene positions.
3. At each reveal fraction, run a full forward pass.
4. Newly revealed positions are replaced by the model prediction and clamped to
   nonnegative values.
5. Previously revealed positions remain fixed.
6. Return the final full prediction from the fourth step.

The implementation will allow deterministic seeds for repeatable inference.

## Data Pipeline

The first version will support AnnData objects and `.h5ad` files. Required obs
fields will be configurable, with defaults:

- `perturbation`: perturbation label.
- `context`: cell type, cell line, donor, or condition context.
- `batch`: batch or replicate id.
- `is_control`: boolean control indicator.

Preprocessing will support:

- Dense and sparse AnnData matrices.
- Raw count to CP10k log1p normalization.
- Option to skip normalization for pre-normalized datasets.
- Gene filtering through a supplied vocabulary.
- Subsampling to `G_prime`, with forced inclusion of the perturbation gene at
  position 1 after CLS.

The set constructor will:

- Group perturbed cells by `(context, perturbation, batch)` where available.
- Chunk or sample sets of `S` target cells.
- Sample matched NTC/control sets from the same context and batch.
- Fall back to context-level controls when batch controls are insufficient.
- Pad incomplete sets by sampling with replacement.

Synthetic data will provide known perturbation effects so tests can verify
training and metrics without external data.

## Prior Embeddings

The clean-room implementation will not ship external biological prior files.
Instead, it will load user-provided files and validate shapes:

- `esm`: `[n_genes, 5120]`
- `string`: `[n_genes, 512]`
- `genept`: `[n_genes, 3072]`
- `depmap`: `[n_genes, 1150]`
- `cell_painting`: `[n_genes, 259]`

Missing files can be allowed for smoke tests; the loader will generate zero
vectors and mark the source as missing. Real training should treat missing files
as a warning unless explicitly configured as an error.

## Losses

The full objective will expose these terms:

- `mmd`: set-level energy distance between predicted and target sets.
- `fold_change_ccc`: CCC between predicted and true pseudobulk deltas.
- `per_gene_ccc`: CCC across cells for each gene.
- `delta_norm`: squared penalty around predicted/true delta norm ratio of 1.
- `delta_mse`: MSE on pseudobulk deltas.
- `contrastive`: InfoNCE over predicted CLS embeddings and target centers.
- `prior_reconstruction`: MSE reconstruction of prior embeddings from projected
  prior tokens.

All weights default to `1.0` for the Ultra-style objective. The config will
allow disabling per-gene CCC for full-dataset phase 2, matching the paper's
description. Tiny tests will verify finite losses and gradients.

## CLI Design

The CLI will be implemented as `xcell-repro`.

Expected commands:

```bash
xcell-repro make-synthetic --output data/synthetic.h5ad --n-cells 512 --n-genes 128
xcell-repro train --config configs/tiny.yaml --adata data/synthetic.h5ad --output runs/tiny
xcell-repro predict --checkpoint runs/tiny/checkpoint.pt --adata data/synthetic.h5ad --perturbation GENE_10 --output runs/tiny/pred.h5ad
xcell-repro evaluate --truth data/synthetic.h5ad --pred runs/tiny/pred.h5ad --output runs/tiny/metrics.json
```

These commands define the supported user workflows. Implementation can add
optional flags, but it should keep these command forms working.

## Error Handling

The code will fail early with clear messages for:

- Missing required AnnData obs fields.
- Perturbation genes absent from the vocabulary when strict mode is enabled.
- Prior embedding files with wrong dimensionality.
- Empty control pools for a requested context.
- Non-finite model outputs or loss values during training.
- Checkpoints whose model config does not match the current code.

Warnings rather than hard failures will be used for optional prior sources in
synthetic or smoke-test mode.

## Testing Strategy

Tests will be written before implementation for each module. The first suite
will cover:

- Model config presets create expected cross-attention layer indices.
- `tiny` forward pass returns expression predictions shaped `[B, S, G_prime]`.
- Missing prior embeddings produce correct key padding masks.
- Diffusion training masks reveal the requested fraction.
- Diffusion inference performs four cumulative updates and is deterministic with
  a fixed seed.
- Losses return finite scalar tensors and propagate gradients.
- AnnData set construction samples matched control and target sets.
- Synthetic CLI data generation creates a valid `.h5ad` file.
- Train and predict smoke tests run on a tiny synthetic dataset.
- Evaluation metrics produce expected keys and finite values.

Full scientific reproduction tests against X-Atlas/Pisces are outside the first
local test suite because the data and weights are not present in this workspace.

## Implementation Order

1. Project packaging, dependency declarations, and config objects.
2. Tests for config, diffusion masks, and prior loaders.
3. Minimal model components and `tiny` forward path.
4. Loss functions and gradient tests.
5. Synthetic AnnData generator and data set constructor.
6. Training loop with checkpointing.
7. Inference loop with four-step remasking.
8. Evaluation metrics and CLI integration.
9. Documentation and final smoke run.

## Risks And Mitigations

- The paper gives architectural details but not every production implementation
  detail. The implementation will mark paper-derived choices explicitly and use
  conservative PyTorch defaults where unspecified.
- The official model weights and inference implementation are not publicly
  available in the checked repository. This reproduction will not claim
  identical predictions to Xaira's unreleased implementation.
- Ultra training requires multi-node H200-scale compute. The code will keep
  Ultra construction and configuration available, but local verification will
  use `tiny`.
- External biological prior files are large and not in the workspace. The
  loader will support real files while tests use deterministic synthetic priors.
- `geomloss` may be unavailable. The loss module will provide a torch energy
  distance fallback and use `geomloss` only when installed.

## Acceptance Criteria

The reproduction is complete for this phase when:

- `pytest` passes.
- A tiny synthetic training run completes and writes a checkpoint.
- A prediction run loads the checkpoint and writes an AnnData file.
- Evaluation produces a metrics JSON with finite values.
- The README explains the clean-room scope, data expectations, and commands.
- The code exposes `tiny`, `mini`, and `ultra` configs.
